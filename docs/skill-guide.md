# Skill 自建指南——把 Claude 变成你的 SAP 数字员工

> sap-driver 的工具链(RFC/MCP/桥/前端)开源了,但**技能编排层不在本仓**——那是作者的私有工作流。
> 这不是藏着掖着:技能 = 几个月实跑经验的本体,里面焊死了作者环境的具体对象名、单号、内部流程,
> 脱敏后剩下的就只有形状没有血肉。所以本仓选择**给渔不给鱼**:技能的配方在这里,照抄即可起步。

## 什么是 Skill(为什么不是一个大 prompt)

Skill 是 Claude Code 的能力单元(`~/.claude/skills/<name>/SKILL.md`,frontmatter 声明触发词,正文写流程)。
核心思想:**不是让 AI 每次现想流程,而是把你验证过的流程固化成它每次必走的步骤**。

- 单次会话 prompt = 临时工;Skill = SOP 手册 + 一线经验坑账
- Skill 里可以带脚本(闸门、校验器)、模板(评估表、报告骨架)、参考文档(军规、坑录)
- 触发靠 description 里的自然语言——你不用喊命令,说「评估一下」它自己进场

## 数字员工的最小骨架:4 个 Skill

作者实际跑的交付流水线,收敛成 4 个角色,任何人都能照抄起步:

```
需求进来 ──> [review] 读单评估 ──> 人点头 ──> [build] 写码过闸 ──> 人点头
                │                                  │
                │                                  ├──> [接口文档/测试报告 长出来]
                │                                  └──> [版本比对] ──> 交付
                └──> [ledger] 全程记账(状态机)
```

| Skill | 干什么 | 人的角色 |
|---|---|---|
| **review** | 需求→结构化评估(现状核实/方案比选/人天/风险) | 审评估,拍方案 |
| **build** | 写码 + **质量闸**(语法/SQL 性能/命名规范/危险语句扫描) | 审交付物,点通过 |
| **ledger** | 交付台账:每单的状态流转/产物登记,状态机唯一写入口 | 看板 |
| **flow** | 编排:按单子状态自动决定下一个 skill 进场 | 只看进度 |

## 质量闸是灵魂(别人拿不走的部分)

流程谁都会写;**把「这次没翻车」变成「这类问题结构性不会再翻」**的,是闸门。
以 ABAP 场景为例,作者在 build skill 里挂了一个 `Invoke-DevGate.ps1`,交付前机器判:

| 闸 | 查什么 | 为什么机器判而不是人眼 |
|---|---|---|
| X1 | 禁新语法(老 ECC 编译不过,一个错连坐整个函数组) | 规则明确,机器零疲劳 |
| X2 | SELECT 行数截断写法 | 系统内核怪癖 |
| G1-G5 | SQL 五关:循环内 SELECT / 索引命中 / FAE 三要素 / 往返次数 / 聚合下推 | 每条都是历史上实翻过的车 |
| 危险语句 | COMMIT/ROLLBACK/未授权 DDL | 红线类,零容忍 |

**你自建时的翻译规则**:把这条思路平移到你的技术栈——
每翻一次车,不修完就完,而是问三个问题:
1. 这类错**机器**能查出来吗?(能→写成脚本闸)
2. 是**流程**缺一步吗?(是→写进 skill 流程)
3. 是**知识**缺一块吗?(是→写进军规参考文档)
三问过完,这次翻车才闭环。坑账(`pitfalls.md`)按 `日期/现象/根因/规则` 四段记,新坑当轮增补。

## 坑账驱动:技能是这样长出来的

技能不是设计出来的,是**翻车翻出来的**。作者的 build skill 折叠了 40+ 条实翻实修的坑
(截断线不是 72 是 71、语言键不是 'ZH' 是 '1'、文本池挂 K 类主请求……),
每条都标注「已机械化/交付前自查」。你的第一个 skill 应该只有一个 SKILL.md;翻车了,长一条;
同类坑第二春,长成闸。三个月后它就是你的数字员工和别人的数字员工的差距所在。

## 起步:5 分钟造出你的第一个 Skill

1. 建目录:`~/.claude/skills/sap-review/SKILL.md`(Windows 是 `%USERPROFILE%\.claude\skills\`)
2. 写 frontmatter:

   ```markdown
   ---
   name: sap-review
   description: 需求评审。当用户说"需求评审、评估一下、可行性、估个人天"时使用。
   ---
   ```

3. 正文写你的流程(第一版三行也行):读什么 → 判断什么 → 产出什么
4. 在 Claude Code 里说「评估一下这个需求」,它会自己进场
5. 之后每次交付不顺,回来改 skill 本体,而不是只在对话里救火

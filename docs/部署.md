# SAP Driver 部署指南

从零把 SAP Driver 跑起来,共 6 步。全程约 30-60 分钟(大部分时间在装 NCo 和激活 ABAP)。

## 前置条件

| 依赖 | 要求 | 说明 |
|---|---|---|
| Windows | 10/11 x64 或 Server 2016+ | PowerShell 5.1(系统自带) |
| Node.js | ≥ 20 | 仅 mcp-server 需要 |
| SAP 账号 | 有 SE80/SE37 权限的开发机账号 | 激活 z-rfc 用 |
| NCo 3.1 | SAP NetWeaver RFC SDK / NCo x64 | 见下节 |

## 第 1 步:安装 NCo 3.1(必读)

**SAP NCo DLL 受版权保护,本仓不分发,必须自行下载:**

1. 用 S-user 登录 [SAP Support Portal](https://support.sap.com),搜 **NCO 3.1** 或按 Note 2516885 找下载项,选 **x64** 版
2. 解压得到 `sapnco.dll` + `sapnco_utils.dll`
3. 注册进 GAC_64(管理员 PowerShell):
   ```powershell
   gacutil /i sapnco.dll        # gacutil 来自 .NET SDK;没有的话见下方替代
   gacutil /i sapnco_utils.dll
   ```
   **无 gacutil 的替代**:把两个 DLL 放到 `rfc-frontend/RfcCli/` 目录(gitignore 已排除,不会误提交),并设置环境变量指向该目录:
   ```powershell
   [Environment]::SetEnvironmentVariable('SAP_RFC_FRONTEND', '<DLL所在目录>', 'User')
   ```
4. 验证:
   ```powershell
   cd rfc-frontend/RfcCli
   . .\Invoke-SapRfc.ps1
   # 有报错说找不到 sapnco = GAC/路径没配好
   ```

## 第 2 步:激活 SAP 侧 RFC(12 个 ABAP)

`mcp-server/z-rfc/` 里的 ABAP 需要在你的 SAP 系统激活:

**核心 4 个(最小可用集):**

| 文件 | 功能组 | 用途 |
|---|---|---|
| `ZLILY_DIAG_Q3.abap` | ZFG_LILY_DIAG4 | 动态 SELECT 查询引擎(sap_query 的真引擎;`RFC_READ_TABLE` 被加固后的唯一可靠读径) |
| `ZLILY_DIAG_QUERY.abap` | 同上 | 旧版查询(RFC_READ_TABLE 分页包装,Q3 不可用时的回退) |
| `LZFG_LILY_DIAG4U01_V3_dualgate.abap` | 同上 include | 双闸权限校验 include |
| `ZLILY_DEV_TR_PUT.abap` | — | 挂 TR 包装器(E071 实查终判) |

**进阶 8 个(按需):**

| 文件 | 用途 |
|---|---|
| `ZLILY_DIAG_GEN_EXEC.abap` 相关 | SE37 变式读写(sap_variant_read/write) |
| `ZLILY_DIAG_SRC_PUT8` / `ZLILY_DIAG_DEL` | 远端 Z/Y 源码修改/删除(sap_dev_create SOURCE_UPDATE) |
| `ZLILY_REPORT_META/SCAN/RUN2/SPOOL.abap` | 报表族:sap-probe 的报表选择屏/后台执行/假脱机回收 |

激活要点:
- 全部函数需勾选 **RFC-enabled**(远程可调用)
- `LZFG_*` 是函数组 include(`U01`),在 SE80 函数组里粘贴
- 每个文件的 `lt_allow` 白名单 fallback 里写着 `<你的SAP用户名>` 占位——改成部署者的账号(或删除该行走配置表)
- 传输:先在开发机激活,经 TR 传到测试机;**生产机建议不装**(治理默认 PRD 只读,装了也用不上)

## 第 3 步:配置环境(全部脱敏占位,按你的环境填)

### 3.1 MCP 服务器环境表

```bash
cd mcp-server
cp systems.example.json systems.json
```
编辑 `systems.json`,把 `<DVP应用服务器IP>` 等占位换成真实地址:

```json
{
  "systems": {
    "DVP": { "appServerHost": "10.x.x.x", "systemNumber": "00", "client": "100", "user": "YOURUSER", "language": "ZH", "role": "dev" },
    "QAS": { "appServerHost": "10.x.x.x", "systemNumber": "00", "client": "200", "user": "YOURUSER", "language": "ZH", "role": "test" },
    "PRD": { "appServerHost": "10.x.x.x", "systemNumber": "00", "client": "300", "user": "YOURUSER", "language": "ZH", "role": "prod" }
  }
}
```
> client 号按你的环境;`role` 字段驱动治理分级(dev 可写/test 白名单/prod 只读);`prdEnabled` 开源默认 **false**(生产只读通道关闭),确认治理配置后自行改 true。

### 3.2 桥的 SAP 环境表

编辑 `bridge/routes/_sap-conn.ps1` 顶部:

```powershell
$script:SapEnvCfg = @{
  DVP = @{ host = '10.x.x.x'; sysNr = '00'; client = '100' }
  QAS = @{ host = '10.x.x.x'; sysNr = '00'; client = '200' }
  PRD = @{ host = '10.x.x.x'; sysNr = '00'; client = '300' }
}
```

### 3.3 桥配置

```bash
cd bridge
cp bridge.config.example.json bridge.config.json
```
默认 `host: 127.0.0.1` 只监听本机——局域网访问改 `+`(需管理员或 netsh urlacl 一次性注册)。

### 3.4 AI 通道(可选,排查/接口文档/测试报告的 AI 分析用)

- **GLM 主通道**:设置环境变量 `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN`(智谱 anthropic 兼容端点;或任何 anthropic 协议端点)
- **备胎(可选)**:`bridge/bridge.config.local.json`(不进 git)里写 `ai.deepseekBaseUrl/Key/Model`,任何 OpenAI chat/completions 兼容端点都行

不配 AI 通道也能跑:读表/排查跳过 AI 总结功能,其余不受影响。

## 第 4 步:起桥

```powershell
cd bridge
powershell -ExecutionPolicy Bypass -File .\Start-Bridge.ps1
```
- token 自动生成到 `%LOCALAPPDATA%\sap-driver\bridge.token`
- 首次会提示监听地址与路由清单
- 验证:`curl http://127.0.0.1:8421/bridge-token` 应返回 token

## 第 5 步:注册 MCP 到 Claude Code

```bash
cd mcp-server
npm install
```

在 Claude Code 的 `.claude.json` 里(项目级 `mcpServers`)注册:

```json
"sap": {
  "command": "powershell.exe",
  "args": ["-NoProfile","-ExecutionPolicy","Bypass","-File","<仓路径>\\mcp-server\\Start-SapMcp.ps1"],
  "env": {
    "SAP_MCP_NODE": "<node.exe 绝对路径>",
    "SAP_MCP_SERVER": "<仓路径>\\mcp-server\\src\\server.js",
    "SAP_MCP_SYSTEMS": "<仓路径>\\mcp-server\\systems.json",
    "SAP_MCP_AUDIT_DIR": "<审计落盘目录>",
    "SAP_MCP_BIN": "<仓路径>\\rfc-frontend\\RfcCli"
  },
  "type": "stdio"
}
```

重启 Claude Code,`/mcp` 应显示 `sap` 已连接。每会话首次使用先 `sap_connect({system:'QAS', password:'…'})`。

### HTTP facade 模式(给 Web UI 的 sap-ask 等路由用)

```bash
cp mcp-server/facade.local.example.json mcp-server/facade.local.json
# 把 token 换成 64 位随机 hex
wscript mcp-server\Start-SapFacade.vbs
```

## 第 6 步:打开 UI

`ui/` 是纯静态 ES modules,任意静态服务器即可:

```powershell
cd ui
python -m http.server 8080
# 浏览器开 http://localhost:8080(需要一个壳页面,见 ui/README.md 的挂载示例)
```

挂进自己的工作台:按 `ui/README.md` 的 A 方式 `WidgetRegistry.get('sap-copilot').mount(container)`。

页面右上「连接设置」里填桥地址(`http://127.0.0.1:8421`)——首次访问会自动 `GET /bridge-token` 补 token,零配置。

## 目录落点约定(全部 env 可覆盖)

| env 变量 | 缺省 | 内容 |
|---|---|---|
| `SAP_MCP_AUDIT_DIR` | `<仓>/data/sap-mcp-audit` | MCP 审计 JSONL |
| `SAP_PROBE_CACHE_DIR` | `<仓>/data/sap-mcp-probe` | 排查/体检缓存 |
| `SAP_PROGRESS_DIR` | `<仓>/data/sap-mcp-ask` | Agent 进度文件 |
| `SAP_TEST_REPORT_DIR` | `<仓>/data/sap-test-reports` | 测试报告 docx |
| `SAP_ARTIFACT_DOCS` | `<仓>/data/artifacts` | 接口文档/需求解读 |
| `SAP_DELIVERY_ROOT` | `<仓>/data/delivery` | 交付台账 |
| `SAP_RFC_FRONTEND` | `<仓>/rfc-frontend/RfcCli` | NCo 前端 DLL 位置 |
| `SAP_MCP_ROOT` | `<仓>/mcp-server` | facade 地址(bridge→mcp) |

## 常见问题

**Q: `RFC_READ_TABLE` 报 TABLE_NOT_AVAILABLE?**
A: 你家系统也加固了(Note 1469041 类)。这正是 `ZLILY_DIAG_Q3` 存在的原因——激活它,sap_query 自动切过去。

**Q: 登录失败锁号?**
A: RFC 登录失败会计入 SAP 失败计数器。先在 SAP GUI 验证密码,再回来;勿连打重试。

**Q: AI 功能报「GLM 调用失败」?**
A: 没配 `ANTHROPIC_BASE_URL/AUTH_TOKEN`,或套餐超额。备胎通道配好后自动降级。

**Q: 桥启动报端口占用?**
A: 改 `bridge.config.json` 的 `port`;或找到占用进程(默认 8421)。
